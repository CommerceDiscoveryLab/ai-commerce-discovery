# 商品被 AI 发现的工作检查表

这个检查表帮助团队定位“看不到商品”的环节；满足某一步不能证明下一步已经发生。

| 阶段 | 可检查的证据 | 项目支持 |
| --- | --- | --- |
| 信息正确 | 商品系统、变体、品牌、型号、实际价库存、明确单位和政策 | 目录格式、字段与关系校验；事实仍由商家确认 |
| 公网可读 | 商品与图片 HTTP 响应、可见正文、canonical、robots、noindex、CDN/WAF | 静态参考页、sitemap、robots 模板、保存 HTML 基础检查 |
| 数据一致 | 可见页面、JSON-LD、feed、结账的同时间价格与库存 | JSON-LD 与目录比对；真实页面和结账需额外核验 |
| 平台接受 | 商家资质、格式校验、处理回执、被拒条目 | 文件准备与官方指南；没有自动提交 |
| 已被发现 | 控制台覆盖、目标爬虫日志、真实查询中的引用或商品结果 | 下面的实验记录建议；没有排名保证 |
| 产生商业价值 | 引流点击、转化、退款、订单利润与对照 | 商家分析系统；本版不提供自动归因 |

优先行动：补齐可核对规格、明确选中变体、保持真实图片与当前价库存、提供公开政策、减少登录与仅 JavaScript 可见的障碍。只有已有真实评价时才考虑评价数据；不要生成假的星级、认证或“最佳商品”主张。

## 测量方式

在发布前记录一组固定且符合用户实际需要的查询，例如“适合 350 mL 饮品的陶瓷杯”或带单位的规格查询，注明平台、模型、是否联网、语言、地区和时间。每次按同样条件重复多次；动态与个性化结果要记录不确定性。

对比改动前后的抓取、收录、回答引用、引流和成交。把缺货、促销、广告投入、季节变化及目录更新作为混杂因素记录。不要把某次回答出现品牌，报告成普遍推荐提升。

可使用[测量记录模板](../examples/measurement-template.csv)，保存 CSV 列：`run_id, timestamp, platform, market, query, observed_product_url, cited_source, price_correct, availability_correct, referral_clicks, notes`。不把客户聊天、个人身份、付款数据或私人会话写入公开仓库。爬虫 User-Agent 可以伪造，需要结合平台控制台或官方验证方法判断。

`llms.txt` 可作为某些团队的实验性入口，但本版不把它当作所有 AI 必然使用的标准，也不靠隐藏提示词让 AI 推荐某个商品。实际帮助要用观察证据验证。
